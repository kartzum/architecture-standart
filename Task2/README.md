## Задание 2. FURPS+ таблица

### Что нужно сделать

> Команда трансформации просит вас обобщить весь набор 
требований в формате FURPS+ таблицы:
Выделите архитектурно-значимые требования. 
В ходе работы учитывайте не только контекст из задания, но и информацию 
о системах компании из блока «IT-ландшафт компании».
По возможности добавьте дополнительные требования, 
которые кажутся вам важными и могут повлиять на решение. 
Напишите обоснование для таких требований в поле «Комментарий».

### FURPS+

| Код  | Требования                                                                                                                     | Комментарий                                                                          |
|------|--------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| F    | Функциональные (Functionality)                                                                                                 |                                                                                      |
| F01  | На сайте для новых клиентов должен отображаться список доступных депозитов с актуальными ставками.                             | Базовый функционал для привлечения клиентов.                                         |
| F02  | Клиент может подать заявку на депозит через сайт, указав Ф. И. О. и номер телефона.                                            | Заявка является заявкой на обратный звонок, а не на полноценное открытие счета.      |
| F03  | Менеджер кол-центра должен видеть заявки в системе и иметь возможность предложить особые условия.                              | Требуется интерфейс в системе кол-центра для работы с заявками.                      |
| F04  | В интернет-банке для существующих клиентов должен отображаться список депозитов с актуальными и персонализированными ставками. |                                                                                      |
| F05  | Авторизованный клиент в интернет-банке может подать заявку на открытие депозита, указав счёт-источник и сумму.                 |                                                                                      |
| F06  | Операция открытия депозита в интернет-банке должна подтверждаться СМС-кодом.                                                   | Используется существующий функционал ядра. Избегать доработок со стороны подрядчика. |
| F07  | Должна быть реализована система управления ставками по депозитам (справочник).                                                 | Избавляет от работы с XLS-файлами. Доступ для бэк-офисов депозитов и кредитов.       |
| F08  | Процесс согласования ставки по заявке должен быть реализован в АБС.                                                            | Существующий процесс переносится в цифровую среду.                                   |
| F09  | На этапе MVP заявка из интернет-банка обрабатывается менеджером бэк-офиса вручную через АБС.                                   | Менеджер подтверждает условия, после чего депозит открывается.                       |
| F10  | Клиент должен получать СМС-уведомления после подтверждения ставки и после успешного открытия депозита.                         | Используется существующий функционал ядра для уведомлений.                           |
|      |                                                                                                                                |                                                                                      |
| U    | Удобство использования (Usability)                                                                                             |                                                                                      |
| U01  | Интерфейсы для клиента (сайт, интернет-банк) должны быть максимально удобными.                                                 |                                                                                      |
| U02  | Все операционные отклики в интерфейсе должны занимать миллисекунды.                                                            |                                                                                      |
| U03  | Интерфейсы должны соответствовать принятой в компании системе дизайна (цвета, брендирование).                                  |                                                                                      |
|      |                                                                                                                                |                                                                                      |
| R    | Надёжность (Reliability)                                                                                                       |                                                                                      |
| R01  | Все сервисы (сайт, интернет-банк, бэк-офисные системы) должны быть доступны 24/7 с uptime 99.9%.                               |                                                                                      |
| R02  | Система должна выдерживать пиковые нагрузки от онлайн-подачи заявок без угрозы для работоспособности банка.                    |                                                                                      |
| R03  | Необходимо обеспечить отказоустойчивость интернет-банка: при сбое в основном ЦОД должен работать резервный.                    |                                                                                      |
| R04  | Система должна поддерживать горизонтальное масштабирование для интернет-банка и связанных сервисов.                            |                                                                                      |
|      |                                                                                                                                |                                                                                      |
| P    | Производительность (Performance)                                                                                               |                                                                                      |
| P01  | Время отклика на все операции в интерфейсе клиента должно быть минимальным (целевой показатель — миллисекунды)                 |                                                                                      |
| P02  | Загрузка справочных данных (например, списка депозитов) не должна занимать более 1 секунды.                                    |                                                                                      |
| P03  | Архитектура должна учитывать, что АБС масштабируется только вертикально.                                                       |                                                                                      |
|      |                                                                                                                                |                                                                                      |
| S    | Поддерживаемость (Supportability)                                                                                              |                                                                                      |
| S01  | Максимально использовать уже существующие в банке технологии (MS SQL, Oracle, и т.д.).                                         | Снижение затрат на внедрение и обучение.                                             |
| S02  | Новые технологии должны быть совместимы с существующими платформами разработки.                                                | Обеспечивает интеграцию и поддержку.                                                 |
| S03  | Предпочтение отдавать технологиям, по которым у сотрудников банка уже есть экспертиза.                                         | Снижение рисков и затрат на привлечение подрядчиков.                                 |
| S04  | Должна быть разработана документация для дальнейшего расширения системы.                                                       | Обеспечивает поддерживаемость и развитие после MVP.                                  |
|      |                                                                                                                                |                                                                                      |
| +R   | + Ограничения (Restrictions)                                                                                                   |                                                                                      |
| +R01 | Защита передаваемых данных (номера телефонов, Ф. И. О., данные по заявкам) с помощью механизма шифрования трафика.             | Требование безопасности для сайта и интернет-банка.                                  |
| +R02 | Избегать прямой интеграции интернет-банка с API АБС в новом процессе.                                                          | Требование для развязки систем и повышения надёжности.                               |
| +R03 | Для асинхронного взаимодействия между сервисами предпочтительнее использовать Kafka.                                           | Технологический выбор на перспективу.                                                |
| +R04 | Текущая версия платформы интернет-банка несовместима с Kafka.                                                                  |                                                                                      |
| +R05 | Рассмотреть возможность перевода только функционала открытия депозитов на микросервисную архитектуру.                          | Стратегическое решение для обхода текущих ограничений платформы.                     |
| +R06 | Реализацию бизнес-функционала, связанного с СМС, предпочтительно выполнять силами команды разработки банка.                    |                                                                                      |
| +R07 | База данных АБС перегружена, новые процессы не должны усугублять ситуацию.                                                     | Критическое ограничение, влияющее на архитектуру.                                    |
|      |                                                                                                                                |                                                                                      |
